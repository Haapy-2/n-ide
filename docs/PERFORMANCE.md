# 성능과 UX 규칙

앞으로의 단계에서 코드를 쓸 때 지킬 규칙. 목표 수치는 [SPEC.md](SPEC.md) 8장, 측정 결과는 [PROGRESS.md](PROGRESS.md).
근거가 된 점검: 2026-11-11 중간 성능 점검(8단계 시점, [log26-11-11.md](log/log26-11-11.md)).

## 1. UX를 지키는 규칙 (가장 먼저)

작가 눈에 보이는 것은 그대로 두고, 안 보이는 일만 줄인다. 최적화와 UX가 부딪치면 UX를 택한다(CLAUDE.md 우선순위 1번).

- 체감이 안 되는 숫자를 맞추려고 화면 동작을 바꾸지 않는다. 목표 미달이면 보고하고 같이 정한다.
- 화면에 보이는 것이 달라질 수 있는 수정(커서, 스크롤, 선택 표시, 깜빡임, 클릭 반응, 한글 조합)은 고치기 전에 아래 네 가지를 보고하고 허락을 받는다.
  1. 무엇을 바꾸나: 파일과 이유
  2. 달라 보일 수 있는 것
  3. 손 확인 목록: 작가가 실제로 하는 동작 3~5개
  4. 문제가 생기면 되돌리는 방법
- 고친 뒤에는 빌드·테스트·성능 측정을 먼저 돌리고, 사용자에게 손 확인 목록을 드린다. 화면이 안 바뀌는 수정은 보고에 "보이는 변화 없음"이라고 적는다.
- 이미 UX를 위해 속도를 양보한 결정은 되돌리지 않는다: 회차 전환 때 본문을 바로 읽기(뒤에서 읽으면 옛 본문이 한 박자 남음), 사이드바 회색 선택 직접 그리기.
- 하지 않기로 한 것: 본문 줄 배치를 보이는 부분만 계산(`allowsNonContiguousLayout`, 스크롤 막대가 튐). 10만 자 넘는 회차가 생기기 전까지.

## 2. 키 입력 경로

키 입력마다 불리는 곳(`textDidChange`, `EpisodeAutosaver.textDidChange`, 9단계 이후 상태 줄)에서 하지 않는 것:

- 본문 전체 훑기나 복사(`textView.string` 읽기 포함). 본문 복사는 저장할 때 한 번만.
- 글자 수 전체 다시 세기, 검색, 스냅샷. 입력이 멈춘 뒤 메인 스레드 밖에서 하고 결과만 화면에 올린다.
- `project.json` 쓰기. 글자 수처럼 자주 바뀌는 값을 넣는다면 묶어서 가끔 저장한다(9단계 설계 때 정함).
- SwiftUI 상태 바꾸기. 바꾸면 그 상태를 보는 뷰 전체가 다시 그려진다.

## 3. 회차 수에 비례하는 일

- 화면 갱신(SwiftUI `body`)마다 회차 배열 전체를 훑거나 새로 만들지 않는다.
- 목록의 한 줄은 별도 뷰로 빼고 그 줄에 필요한 값만 넘긴다. 입력값이 안 바뀐 줄은 다시 그려지지 않는다.
- "ID로 회차 찾기"는 `ProjectModel`의 함수 하나로 모은다. 흩어 두지 않는다.
- 새 기능을 500회차로만 재지 말고, 회차 수에 비례하는 기능이면 3,000회차 더미로도 잰다.
- 지금 남아 있는 것(17단계 대상): 사이드바가 회차 줄 500개를 모두 만들고 선택이 바뀔 때마다 다시 훑음(`EpisodeList.swift`, `WorkspaceView.swift`의 ID 배열 감시).

## 4. AppKit과 SwiftUI 사이

- 때를 추측하지 않는다. "조금 뒤에 한 번"(`DispatchQueue.main.async`)으로 시점을 맞추지 말고, AppKit이 알려 주는 자리를 쓴다. 예: 창에 붙는 순간은 `viewDidMoveToWindow`.
  (실행 측정이 가끔 멈추던 원인이 이것이었다. 편집기가 창에 붙기 전에 초점 주기가 실행돼 초점도 창 감시도 걸리지 않았다.)
- `updateNSView`에서 텍스트를 다시 넣지 않는다(CLAUDE.md). 바뀐 값이 있을 때만 그 부분을 적용한다.
- 매번 계산되는 값(`EditorStyle`의 글꼴·문단 모양)을 자주 부르게 되면 한 번 만들어 둔다.

## 5. 메인 스레드

- 파일 쓰기, 외부 변경 확인, 스냅샷은 메인 스레드 밖에서.
- 회차 전환 때 읽기만 예외(5,000자 안팎, 0.1ms). 작품이 느린 디스크에 있거나 회차가 수백 KB면 큰 파일만 뒤에서 읽는다.

## 6. 측정

- 새 기능을 넣으면 그 경로를 성능 측정에도 넣는다. 지금 키 입력·회차 전환 측정은 편집기 뷰만 따로 재서 자동 저장기, SwiftUI, 사이드바가 빠져 있다.
- 실행 시간 측정은 한 번에 10초 제한. 넘기면 멈춘 것으로 세고 표 아래에 적는다(`Scripts/perf.sh`).
- 메모리는 창 크기를 1100×760으로 고정하고 잰다(`LaunchProbe.windowContentSize`). 창 크기에 따라 그래픽 버퍼가 달라져 값이 흔들린다.
- 측정용 코드는 환경 변수가 있을 때만 동작하고, 측정 신호는 화면을 그린 뒤에 찍는다(실제보다 짧게 나오지 않게).
- 실행 시간을 줄이기 전에 구간별로 잰다: 앱 시작 → 작품 선택 창 → 작업 공간 → 편집기 입력 가능.
