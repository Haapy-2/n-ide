# 개발 계획

요구사항 원문은 [SPEC.md](SPEC.md), 디자인 값은 [DESIGN.md](DESIGN.md).
각 단계는 **빌드되고, 사용자가 직접 실행해서 확인할 수 있는 상태**로 끝난다.
크기: 작음(한 세션의 1/3 이하) · 중간(한 세션의 절반 정도). "큼"은 모두 쪼갰다.

| 디자인 스냅샷 | 앱 테스트에서 각 화면을 라이트/다크로 그려 PNG로 `docs/design-snapshots/`에 저장 | 손으로 캡처하지 않아도 단계마다 같은 조건으로 다시 만들 수 있다. 1단계에서 동작 확인 |

## 3. 순서 조정 제안 (SPEC 10장 권장 순서와 다른 점)

1. **작품 열기와 사이드바 목록을 편집기보다 먼저** 만든다. 편집할 회차를 고르는 화면이 있어야 편집기를 실제 상황에서 확인할 수 있다.
2. **성능 측정 도구를 3단계에 일찍** 만든다. 그래야 이후 모든 단계 보고에 측정 표를 붙일 수 있다.
3. **"회차 관리와 자동 저장"을 둘로 나누고 자동 저장을 먼저** 한다. 저장을 편집기 바로 다음에 검증하라는 SPEC 취지를 따른 것이다.
4. **스냅샷을 검색·바꾸기보다 먼저** 만든다. 전체 바꾸기가 실행 직전에 스냅샷을 찍어야 하기 때문이다.
5. **설정 창을 따로 한 단계**로 둔다. 편집기 단계를 작게 유지하려는 것이다. 그 전까지는 DESIGN.md 기본값으로 고정된다.

| 4 | 작품 선택 창과 사이드바, 성능 도구 | 중간 | 앱을 켜면 작품 선택 창이 뜨고, 더미 500회차 작품을 골라 작업 공간의 사이드바 목록 확인. `Scripts/perf.sh` 표 출력 |

### 단계별 내용

**1. 앱 뼈대** — `NovelEditor.xcodeproj`(앱 타깃, 앱 테스트 타깃), NovelCore 빈 패키지 연결, `Scripts/build.sh`·`run.sh`·`test.sh`(로그는 `build/logs/`), 앱 이름 한곳 관리, 색 토큰 파일, Pretendard 번들(공식 저장소에서 받아 `App/Resources/Fonts/`에 라이선스와 함께), 창 구조(사이드바 + 편집 영역 자리) 와 빈 화면 안내, `docs/PROGRESS.md` 생성, 디자인 스냅샷 생성 방식 확정.

**2. NovelCore 저장 기본** — 모델(작품, 회차, 노트), `project.json` 읽기/쓰기와 `schemaVersion`, 원자적 쓰기, 회차 본문 읽기/쓰기(UTF-8), 고유 ID 파일 이름, 모르는 상위 버전 열기 거부. 단위 테스트.

**3. 저장 순서와 복구** — 회차별 저장 줄(한 번에 하나씩)과 변경 번호, 늦게 끝난 옛 저장이 최신을 덮지 못하는 것을 재현하는 테스트, `project.json.bak` 유지, 깨진 `project.json` → 백업 → `episodes/`로 목록 재구성, 저장 실패 재시도. 단위 테스트.

**4. 작품 선택 창과 사이드바, 성능 도구** — 실행하면 뜨는 작품 선택 창(최근 작품 목록, 새 작품, 다른 위치에서 열기), 작품을 고르면 작업 공간 창으로 이동, "작품 전환…" 메뉴, 사이드바 회차 목록(번호, 제목, 글자 수 자리), `project.json`만 읽고 본문은 읽지 않기. `make-dummy-novel`(500회차 × 5,000자, `build/perf/` 아래 생성), `Scripts/perf.sh`, "500회차 열기" 측정.

**5. 편집기와 한글 입력** — `NSTextView`(TextKit 1 명시) 래퍼, 편집 영역 기본값(본문 폭 고정, 줄·문단 간격, 위아래 여백, 마지막 줄을 가운데까지 올리는 아래 여백), 선택 회차만 읽어 표시, 회차 전환 시 실행 취소 기록 비우기. `docs/checklist-hangul.md` 작성. "키 입력", "회차 전환", "앱 실행", "대기 메모리" 측정 추가.

**6. 자동 저장** — 입력이 멈추면 저장, 회차 전환·창 비활성화·앱 종료 때 저장, 종료 시 진행 중 저장 완료 대기, 실패 시 재시도 후 눈에 띄는 표시, 실패 상태로 닫으면 경고. 조합 중 저장이 조합을 끊지 않는지 확인.

**7. 회차 관리** — 추가, 이름 변경, 삭제(확인 → 휴지통, 휴지통 이동 실패 시 중단), 드래그 순서 변경. 각 동작의 메뉴와 단축키.

**8. 외부 변경 처리** — 창 활성화 때와 저장 직전에 파일 변경 확인, 앱 쪽 변경이 없으면 조용히 다시 읽기, 양쪽 다 바뀌었으면 앱 쪽을 스냅샷으로 남기고 선택 묻기.

**9. 글자 수와 상태 표시줄** — 공백 포함/제외, 표시 방식(포함/제외/둘 다)과 목표 기준(포함/제외) 선택 설정(백그라운드 계산, 먼저 전체 계산 속도를 재고 느리면 증분 계산), 회차별 목표와 진행률, 사이드바 글자 수, 상태 줄 흐려짐/다시 나타남, 저장 중·실패 표시.

**10. 설정 창** — 본문 글꼴 3종, 글자 크기, 줄 간격, 문단 간격, 본문 폭, 글자 수 표시 방식·목표 기준(결정 사항 3), **사이드바 뒤로 창(다른 앱·바탕화면) 비치기 켜기/끄기**(기본 켬, 2026-11-10 사용자 요청. 효과는 6단계 후속 수정에서 이미 들어갔고 키는 `AppSettingKey.sidebarSeesThroughWindow`). 설정 저장 위치는 결정 사항 6 참고.

**11. 버전 스냅샷** — 수동 찍기, 10분 자동 찍기와 회차를 떠날 때 찍기, 보관 상한 50(자동만 정리), 목록·내용 보기·복원.

**12. 작품 전체 검색** — 백그라운드에서 모든 회차 검색(줄 단위, 대소문자 옵션), 결과 목록, 클릭하면 해당 회차의 위치로 이동. 첫 검색/두 번째 검색 측정.

**13. 전체 바꾸기** — 대상 개수 표시와 확인, 실행 직전 해당 회차 전부 스냅샷, 한 번의 실행 취소로 전부 되돌리기(어려우면 스냅샷 복원 안내). 되돌리기 방식은 9장 4번.

**14. 집중 모드와 타자기 스크롤** — 사이드바·상태 줄 숨김, 입력 줄을 세로 가운데 근처로 유지(조합을 끊지 않는지 확인).

**15. 설정 노트 분할 화면** — 노트 목록, 노트 추가/이름 변경/삭제, 본문 옆 분할 표시, 노트 자동 저장.

**16. 내보내기** — 선택 회차 또는 전체, txt/md, 한 파일로 합치기("N화 제목" + 빈 줄) 또는 회차별 파일.

**17. 마무리 최적화** — 성능 목표 전체 측정과 미달 항목 보고, 메뉴·단축키 전체 점검, 앱 아이콘, 문서 정리.

## 5. 세부 기준 (SPEC 7장 제안값, 확인 필요)

SPEC에 있던 값:

- **글자 수**: `String.count`(보이는 글자 단위). "공백 포함"은 줄바꿈만 빼고 모두, "공백 제외"는 공백·탭·줄바꿈을 뺀다. 조합 중인 글자도 한 글자.
- **자동 스냅샷**: 내용이 바뀐 회차만 10분마다, 그리고 회차를 떠날 때(전환, 종료) 마지막 스냅샷과 다르면. 회차당 최근 50개, 넘으면 오래된 자동 스냅샷부터 삭제. 수동 스냅샷은 자동으로 지우지 않는다.
- **검색**: 입력한 문구 그대로. 영문 대소문자 구분 안 함이 기본(옵션으로 켬). 줄을 넘는 검색 없음.
- **전체 바꾸기**: 실행 직전 바뀌는 회차 전부 스냅샷. 한 번의 실행 취소로 전부 되돌리기, 어려우면 스냅샷 복원 안내.
- **회차 삭제**: 휴지통으로 못 옮기면 중단하고 알림. 영구 삭제로 대신하지 않는다.
- **내보내기**: 전체는 회차 순서대로 한 파일, 회차마다 "N화 제목" 줄과 빈 줄로 구분. 회차별 파일 옵션.
- **실행 취소**: 회차를 전환하면 기록을 비운다. 전환 때 찍는 스냅샷이 안전망.

구현하려면 정해야 해서 내가 추가로 제안하는 값:

- **자동 저장 지연**: 입력이 멈추고 1초 뒤 저장.
- **저장 재시도**: 0.5초, 1초, 2초 뒤 세 번 다시 시도. 그래도 실패하면 상태 줄에 error 색으로 표시하고 계속 유지.
- **회차 번호**: 파일에 저장하지 않고 목록 순서로 매긴다(1화, 2화…). 순서를 바꾸면 번호도 바뀐다.
- **새 회차 제목**: 비워 두고 사이드바에 inkMuted로 "제목 없음"이라고 보인다.
- **목표 글자 수 기본값**: 새 회차마다 5,000자. 회차별로 바꿀 수 있다. 어느 기준(공백 포함/제외)으로 셀지는 설정을 따른다(결정 사항 3).
- **텍스트 파일 형식**: UTF-8, BOM 없음, 줄바꿈 LF. 내보내기도 같다.
- **외부 변경 감지**: 파일의 수정 시각과 크기로 1차 확인, 다르면 내용을 비교해 실제로 바뀌었는지 판단.

## 8. 추가 기능 아이디어

### 회차 묶음 (2026-11-10 사용자 요청)

사이드바에서 회차를 여러 개 골라(⌘클릭, ⇧클릭) 하나의 묶음(예: "1부 귀환", "2장 북부")으로 묶는다. 묶음은 접고 펼 수 있고, 이름을 바꾸고, 풀 수 있다.

| | A안: 진짜 폴더 | B안: 보이는 것만 묶기 (추천) |
|---|---|---|
| 저장 방식 | `episodes/1부 귀환/<ID>.md`처럼 파일을 하위 폴더로 옮긴다 | 파일은 `episodes/`에 그대로 두고, `project.json`에 묶음 이름과 그 안의 회차 ID 목록만 적는다 |
| Finder에서 | 묶음이 폴더로 보인다 | 묶음이 보이지 않는다(앱 안에서만) |
| 원고 안전 | 묶고 풀 때마다 파일을 옮겨야 해서 도중 실패·외부 변경·복구가 복잡해진다. "파일 이름(위치)은 바뀌지 않는다"는 원칙과도 부딪친다 | 파일을 전혀 건드리지 않는다. 묶음 정보가 깨져도 회차 목록 복구(3단계)로 본문은 그대로 돌아온다 |
| 순서·번호 | 폴더 안팎 순서를 따로 관리해야 한다 | 지금처럼 `episodes` 배열 순서 하나로 번호를 매기고, 묶음은 그 위에 얹는 표시일 뿐이다 |
| 나중에 iOS | 폴더 구조를 그대로 옮겨야 한다 | `project.json`만 읽으면 된다 |
| 형식 변경 | 폴더 구조 변경 + `schemaVersion` 올림 | `project.json`에 `groups` 추가 + `schemaVersion` 2로 올림(1→2 옮기기 코드 포함) |

- B안에서 회차 번호(1화, 2화…)는 묶음과 상관없이 작품 전체에서 이어진다. 묶음별로 번호를 다시 매길지는 그때 정한다.
- 크기: 중간(묶기·풀기·이름 바꾸기·접기, 여러 개 선택, 형식 버전 2와 옮기기 코드, 테스트). 7단계에서 여러 개 선택과 드래그를 만들고 나서 붙이는 것이 자연스럽다.
- 묶기·풀기·묶음 이름 변경도 ⌘Z로 되돌린다(9장 5번).

## 9. 되돌리기(⌘Z) 정책

2026-11-11 사용자와 정함. 되돌리기 기록은 **초점 위치로 나눈다**: 본문에 초점이 있으면 글자 되돌리기(회차마다 따로, 회차를 바꾸면 비움), 사이드바에 초점이 있으면 회차 목록 되돌리기(창마다 하나). 섞이면 ⌘Z가 무엇을 되돌릴지 예측하기 어려워서다.

| # | 대상 | 상태 | 되돌리기(⌘Z) | 다시 실행(⇧⌘Z) | 언제 |
|---|---|---|---|---|---|
| 1 | 새 회차 | 완료 | 방금 만든 회차를 휴지통으로 | 휴지통에서 꺼내 같은 자리로 | 7단계 |
| 2 | 휴지통으로 이동 | 완료 | 휴지통에서 꺼내 원래 자리·본문 그대로 | 다시 휴지통으로 | 7단계 |
| — | 순서 변경, 이름 변경 | 완료 | 직전 목록으로 | 바꾼 목록으로 | 7단계 |
| 3 | 메뉴에 보이기 | 계획 | 사이드바 우클릭 메뉴 맨 위에 "실행 취소: 순서 변경" 같은 항목. 되돌릴 것이 없으면 흐리게 | "다시 실행: …" | 7단계 마무리 또는 17단계 |
| 4 | 전체 바꾸기 | 계획 | 바뀐 회차 전부를 한 번에 원래 본문으로 | 다시 전부 바꾸기 | 13단계 |
| 5 | 회차 묶음 | 계획 | 묶기·풀기·묶음 이름 변경을 직전 상태로 | 다시 적용 | 묶음 단계(미결정 10) |

### 3. 메뉴에 보이기
- 편집 메뉴의 "실행 취소 / 다시 실행"은 시스템이 이미 이름을 붙여 보여 준다("순서 변경 실행 취소").
- 사이드바 우클릭 메뉴에도 같은 두 항목을 맨 위에 넣어, 단축키를 몰라도 찾을 수 있게 한다. 창의 UndoManager에서 `undoActionName`·`canUndo`를 읽어 이름과 흐림을 정한다.
- 크기: 작음.

### 4. 전체 바꾸기 되돌리기
- 바꾸기 직전에 바뀌는 회차 전부를 스냅샷으로 남긴다(SPEC 7장 세부 기준). 되돌리기 기록에는 회차별 "바꾸기 전 본문"과 "바꾼 뒤 본문"을 함께 넣는다.
- ⌘Z: 각 회차를 바꾸기 전 본문으로 되돌려 쓴다. 단, 그 회차가 바꾸기 뒤에 또 고쳐졌으면(지금 본문 ≠ 바꾼 뒤 본문) 그 회차는 건너뛰고 "N개 회차는 그 뒤에 고쳐서 되돌리지 않았어요. 스냅샷에서 복원할 수 있어요"라고 알린다. 사용자가 새로 쓴 글을 덮지 않기 위해서다.
- 쓰기는 회차마다 저장 줄(`SaveQueue`)로, 변경 번호를 올려서. 지금 열린 회차는 편집기 본문도 함께 바꾼다(조합 중이면 조합이 끝난 뒤).
- 이 기록은 편집 메뉴에서 어느 초점에서든 되돌릴 수 있게 창의 UndoManager에 둔다(작품 전체에 걸친 작업이므로).
- 크기: 중간(13단계 안에 포함).

### 5. 회차 묶음 되돌리기
- B안(보이는 것만 묶기)이면 묶음 정보는 `project.json`의 목록이라, 지금의 순서 변경 되돌리기와 같은 방식(바꾸기 전 목록 통째로 기록)으로 된다. 파일을 건드리지 않아 안전하다.
- A안(진짜 폴더)이면 파일 옮기기를 되돌려야 해서 휴지통 되돌리기처럼 파일별 기록이 필요하다. B안을 추천하는 이유 중 하나.
- 크기: 작음(묶음 단계 안에 포함).
