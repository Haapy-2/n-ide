## 알려진 문제

- 디자인 스냅샷은 창을 화면 밖에서 그려 뜨는 방식이라 **사이드바(유리 패널과 그 안의 회차 목록)가 통째로 하얗게 찍힌다**. 사이드바는 실제 앱이나 Xcode 미리보기로 확인한다. 자동으로 찍으려면 화면 기록 권한이 필요해서 보류.
- **실행 측정 중 가끔 멈춤 → 해결** (2026-11-11): 편집기가 창에 붙기 전에 "다음 차례에 한 번" 초점 주기가 실행되면 초점도 창 감시도 걸리지 않았다(멈춘 앱에서 창의 첫 응답자가 창 자신이었음). `viewDidMoveToWindow`에서 처리하도록 고침. 같은 때 이전 코드 30번 중 6번 멈춤 → 수정 후 30번 중 0번. 이 경우 그 회차에서 "창 비활성 때 바로 저장"과 "돌아왔을 때 외부 변경 확인"도 빠져 있었다.
- 사이드바 여닫기 끊김: Xcode 미리보기에서만 보였고, 실제 앱(Release, 500회차)에서는 문제 없음을 사용자가 확인(2026-11-10). 해결됨.

2026-11-11 (중간 점검 뒤 수정), M2 8GB, 릴리스 빌드. 더미: 500회차(앞 10화 5,000자, 나머지 300자). `Scripts/perf.sh`

|---|---|---|---|---|---|

| 키 입력 1,000번 (5,000자 회차) | p95 1.2ms | 0.2ms | 28.4ms | 16ms 이내 | 통과 |

| 앱 실행 → 입력 가능 (첫 실행 제외 5회) | 중앙값 562.2ms | 540.0ms | 631.2ms | 500ms 이내 | **미달** (아래) |
| 대기 메모리 (5,000자 회차, 30초 뒤, 창 1100×760) | 73.0MB | | | 100MB 이내 | 통과 |

- 메모리 측정 방법이 바뀌었다: 전에는 macOS가 기억한 창 크기(이번 기기 1367×994)로 쟀고 90~112MB로 흔들렸다. 이제 창을 1100×760으로 고정한다. 그래픽 버퍼(IOSurface)가 33MB → 19MB. 앱 코드가 줄어든 것은 아니다.
- 앱 실행: 수정 전후 같은 때 15번씩 두 번 비교해 중앙값 577·539ms(이전) 대 569·546ms(수정) → 속도 차이 없음. 같은 날 오전에는 이전 코드가 483~499ms였다. 기기 상태에 따라 500ms 위아래를 오간다. 17단계에서 구간별로 재고 줄인다(`docs/PERFORMANCE.md` 6장).
- perf.sh 실행 측정에 10초 제한이 생겨 멈춰도 끝까지 돈다. 이번에는 멈춘 실행 없음.

### 미달 원인 조사 (2026-11-10)

- 대기 메모리는 **본문과 거의 무관**하다. 같은 조건에서 500회차 작품 139MB, 1회차 300자 작품 139MB, `backgroundExtensionEffect`를 꺼도 138MB, 작품 선택 창만 띄워도 168MB.
- 큰 덩어리: IOSurface 56~75MB(창·레이어 그래픽 버퍼, 리퀴드 글래스 합성 포함으로 추정), Malloc Small 약 50MB(출처 미확인). 나머지는 합쳐 20MB 남짓.
- 즉 SwiftUI 창 + 리퀴드 글래스의 바탕 비용으로 보이며, 앱 코드가 본문을 쌓아 두는 문제는 아니다. 정확한 출처는 Instruments로 봐야 한다.
- 앱 실행 718ms에는 작품 선택 창을 만든 뒤 작업 공간 창으로 바꾸고 본문을 읽는 과정이 다 들어 있다. 구간별 내역은 아직 안 쟀다.
