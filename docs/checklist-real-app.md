# 실제 앱 확인 목록 (2026-11-26 고친 것)

자동 테스트로는 닿지 않는 부분(메뉴 흐림, 키보드 초점, 실제 입력기)을 실제 앱에서 확인한다.
Claude Code에서 이 파일을 열고 "docs/checklist-real-app.md 순서대로 verify-noveleditor 스킬로 확인해 줘"라고 하면 된다.
화면 제어 권한(컴퓨터 유스)을 허락해야 한다. 한글 조합 항목은 실제 키(`build/verify/keys`)라 잠시 화면을 빼앗는다.

## 준비

1. 사용자의 NovelEditor가 켜져 있으면 끈다(검증 앱과 설정 저장소가 같다).
2. `.claude/skills/verify-noveleditor/verify.sh launch` → 검증 작품(1·2·3화, 각 약 300자)이 열린 앱. 샌드박스 밖에서 실행한다(launch·`keys`·cleanup 모두). 샌드박스 안에서는 명령이 끝날 때 앱이 꺼지고 `keys`가 앱에 닿지 않는다. 한글 자판에서 컴퓨터 유스 `cmd+글자`는 키 코드 0이라 엉뚱한 키가 되니 `app_menu`나 `keys`를 쓴다.
3. computer-use `request_access`에 `com.haapy2.NovelEditor`.
4. 끝나면 꼭 `verify.sh evidence <이름>` → `verify.sh cleanup`(설정 되돌리기, 검증 작품 지우기).

디스크 확인은 `grep -c <표시 문구> "build/verify/run/검증 작품.novel/episodes/"*.md`, 스냅샷은 `ls "build/verify/run/검증 작품.novel/snapshots/"*/`. 본문을 통째로 읽지 않는다.

## 확인하지 못한 채 남은 것

- 충돌 창의 새 문구("…스냅샷으로 남기지 못해 바꾸지 않았어요")는 디스크를 일부러 막아야 해서 이 목록에 넣지 않았다. 자동 테스트(`ExternalChangeTests`)로만 확인했다.
- 단축키 막는 표의 전체 화면 ⌃⌘F 충돌은 실제 앱 보기 메뉴에 그 항목이 있는지부터 본다.
