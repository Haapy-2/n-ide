## 설정 창 "커서": 두께·높이·색(라이트/다크 따로)·미리 보기·기본값으로
- **이유**: 사용자 요청 "커서 폭, 높이, 색을 설정할 수 있게, 색은 컬러 피커와 팔레트, 그 섹션에서만 기본값으로 초기화하는 버튼". 계획 중 추가 요청: 두께는 슬라이더 대신 입력(최대 4), 미리 보기, 다크·라이트 따로.
- **근거**: 편집기 화면은 700×640 창에 스크롤 없이 딱 맞음 → 넣으면 스크롤이 생겨 물었고, 사용자가 "새로 만들어"(왼쪽 목록에 따로)로 정함. "다크/라이트 따로"는 색만 따로로 읽음(두께·높이는 같이). DESIGN 3장 커서 기본값(2pt, 1.2배, accent).
- **결과**:
  - `App/Editor/CaretSettings.swift`: `CaretPalette`(accent·ink·caretRed·caretGreen·caretOrange), `CaretColor`(팔레트 이름 또는 `#RRGGBB`로 저장, 빈 글자 = 기본), `CaretStyle`(창 모양에 따라 바뀌는 `dynamicColor`), `CaretStyleSettings`(UserDefaults 네 키, `reset()`).
  - `EditorSetting.caretWidth`(1~4, 0.5 단위), `caretHeightRatio`(1.0~1.75, 0.05 단위). 색 세 개 `Colors.xcassets`·`ColorTokens`·DESIGN 1장.
  - `ManuscriptTextView.caret`: 바뀌면 커서 색을 넣고 옛 커서 자리를 지운 뒤 바로 다시 그림. 본문은 다시 배치하지 않음. `InsertionCaret.swift`는 고정값 대신 `caret.width`·`caret.heightRatio`.
  - `App/Settings/CaretSettingsPane.swift`: 미리 보기(한 줄, 깜빡이지 않음), 두께 입력 칸(엔터·칸 벗어날 때 맞춤), 높이 슬라이더, 모드 세그먼트, 팔레트 + 컬러 피커, `기본값으로`(이미 기본이면 흐림).
  - 테스트 `CaretSettingsTests` 4개. 앱 162개(건너뜀 11), NovelCore 106개, iOS 빌드 확인 통과. 스냅샷 `10-settings-caret` 라이트/다크, 다른 설정 스냅샷은 목록 한 줄이 늘어 다시 찍힘.
- **에러**: 스냅샷을 다시 찍으면서 이번 변경과 상관없는 `11-snapshot-panel` 두 장도 바뀜 → 되돌림.

## 전체 점검(병목·메모리·안정성)과 저장 쪽 두 곳 고침 (`14a321f`)
- **이유**: 사용자 요청 "작업 코드를 전체적으로 보고 병목, 메모리 효율, 코드 최적화, 버그 가능성, 안정성, 속도 개선".
- **근거**: 앱·NovelCore 코드 전체 읽기 + 기존 측정표(PROGRESS "최근 성능 측정"): 키 입력 p95 1.1ms, 줄 번호 켠 10만 자 1.2ms, 회차 전환 2.3ms, 대기 메모리 75~87MB로 모두 목표 안, 앱 실행만 500ms 경계(17단계로 미룸, 사용자 결정). 회차 전환 때 malloc이 조금씩 느는 것은 2026-11-17 조사로 SwiftUI·AppKit 내부 캐시. 보고 뒤 사용자 결정: ①② 고치기, ③ 기록 코드는 두고 로그만 비우기.
- **결과**:
  - 성능·메모리: 고칠 곳 없음. 검토했지만 그대로 둔 것: 줄 번호를 처음부터 세기(1.2ms), `project.json` 저장 때 기존 파일 해석(백업 보호, 메인 스레드 밖), 종료 때 2ms 간격 확인(종료 때만), 알림·이벤트 감시(모두 해제 짝 맞음).
  - ① `EpisodeAutosaver`: 저장 실패 본문(`unsaved`)과 쓰는 중인 본문(`inFlight`)을 변경 번호와 함께(`SaveJob`) 둔다. `pendingText`는 둘 다 있으면 번호가 큰 쪽. 저장이 성공하면 그보다 같거나 옛 `unsaved`만 지운다. 늦게 끝난 옛 실패가 더 새 `unsaved`를 덮지 않는다.
  - ② `startSave()`(창 비활성, `flush` 앞부분을 뺀 것)와 `startFinishing()`(창 닫기 `onDisappear`)을 그 자리에서 부른다. 전에는 둘 다 `Task` 안이라 창 닫기 처리가 끝난 뒤에 돌아, 그사이 편집기(약한 참조)가 사라지면 마지막 1초 입력을 못 읽을 수 있었다(실제 앱 재현은 안 함, 구조상 위험).

  - 테스트 2개(`testQuickReturnAfterFailedSaveShowsNewestText`, `testStartSaveCopiesTextRightAway`). 앱 164개(건너뜀 11)·NovelCore 106개·iOS 빌드 확인 통과. perf.sh는 안 돌림(바뀐 곳은 저장 경로와 창 비활성·닫기 때 한 번뿐, 키 입력·회차 전환 경로는 그대로).
