## ⌘D 입력기 실험 (a4ecc7a)

- **이유**: 13-2(⌘D 여러 커서)를 VS Code와 같은 경험으로 만들 수 있는지, 한글 입력기가 실제로 어떻게 부르는지 짜기 전에 확인(PLAN 16장 5번, 사용자 허락).

- **결과**: 두벌식 입력기는 바꾸기 방식(ⓐ)과 표시된 글자 방식(ⓑ)을 쓰고 앱마다 기억한다. 여러 커서는 두 방식 모두 세 자리 동시 입력, 키 간격 11ms 24키 어긋남 0, 지우기·엔터가 맞았다. 커서 이동과 `discardMarkedText`는 조합을 끝낸다.

- **수정**: ① HID 키 코드를 보내는 작은 도구로 바꿨다. ② 기록 위치를 인자로 받아 임시 폴더에 썼다. ③ 키마다 플래그를 명시. ④ 확정은 표시된 범위를 바꾸게. ⑤ 입력기 커서를 맨 앞 커서로 두고, 새 번들 ID로 다시 시험해 통과. ⑥ 폴더는 남겨 두고 사용자에게 알렸다.

## 한글 실행 취소 단위 고침 (해시는 다음 기록에)

- **이유**: 입력기 실험에서 macOS 27 두벌식이 표시된 글자 없이 조합한다는 것을 알았고, 그러면 지금 앱의 "조합이 끝난 한 글자가 한 단위" 규칙이 깨질 수 있었다. 사용자가 확인을 요청했다.
- **근거**: 실제 앱(검증 스킬)에 실제 키 코드로 " 도윤 가가"를 치고 ⌘Z → "도윤 각". 입력기 호출 기록(ㄱ → 가 → 각 → 가 + 가, 뒤 셋은 `replacementRange`로 앞 글자 바꾸기).
- **결과**: `ManuscriptTextView.insertText`에서 새 글자는 직접 한 단위(`InputUndoUnit`, 참조형)로 기록하고 NSTextView의 기록은 끈다. 입력기가 그 글자를 고치면 범위만 늘린다. 되돌리기는 범위를 검사하고 반대 기록을 직접 남긴다. 표시된 글자 방식과 다른 범위의 바꾸기는 예전 길 그대로. 실제 앱에서 ⌘Z 한 번에 한 글자, ⇧⌘Z로 복원, 이어 친 글이 디스크에 있음(증거 `build/verify/evidence/20261122-093339-undo-syllable`). 검증 스킬에 `keys.swift`.
- **에러**: ① 처음엔 "새 글자일 때만 끊기"로 했으나 NSTextView가 범위 바꾸기를 합치지 않아 그대로 "각". ② 직접 기록으로 바꾼 뒤 되돌리기 안에서 NSTextView가 스스로 남긴 다시 실행 기록이 범위가 어긋나 `NSRangeException`(테스트 둘이 죽음). ③ 테스트에서 키마다 묶음을 직접 여닫으면 빈 묶음이 ⌘Z 한 번씩을 먹어 실패처럼 보였다.
- **수정**: ① 직접 기록 방식으로. ② 되돌리기 동안 NSTextView 기록을 끄고 반대 기록을 직접 남김, 범위 밖이면 아무것도 안 바꿈. ③ 테스트는 보이는 글이 바뀐 단계만 세게 바꾸고, 실제 앱에서 빈 단계가 없는 것을 따로 확인했다.
