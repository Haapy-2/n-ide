- **이유**: 다음 작업인 13단계 전체 바꾸기를 정하면서, 사용자가 여러 회차 이름 바꾸기, 바뀐 다른 회차를 스냅샷에서 보기, VS Code의 ⌘D 여러 커서, VS Code에서 배울 글쓰기 안정성을 함께 요청했다.

- **결과**: PLAN 14장(전체 바꾸기 상세), 15장(여러 회차 이름 바꾸기), 16장(⌘D: VS Code는 숨긴 입력 칸으로 조합을 받고 조합이 바뀔 때마다 모든 커서에서 문서를 실제로 고친다), 17장(원고 안전 장치 후보 13개, 이미 VS Code보다 강한 것 4개). 미결정 20~23 추가. 코드 변경 없음.
- **에러**: REA `analyze_javascript_application`이 22MB 압축 파일을 문법 분석하지 못했다(parse failure 1, 의미 그래프 비어 있음). 처음 낸 ⌘D 안("다른 자리는 띄어쓰기 뒤에 따라오기")은 VS Code와 달라 사용자 경험을 해쳐 버렸다.
- **수정**: 같은 실제 파일에서 코드를 직접 찾아 읽어 확인했다(실행 관찰은 아님). ⌘D는 여러 커서일 때만 편집기가 입력기 약속(`NSTextInputClient`)을 직접 맡는 방식으로 바꾸고, 한글 규칙 예외는 실험 뒤 허락을 받기로 했다.
