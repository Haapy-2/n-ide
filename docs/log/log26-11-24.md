- **이유**: 전체 바꾸기·되돌리기(13단계)의 마지막 단계(PLAN 14장 7번).
- **근거**: 사용자가 미결정 26(되돌리기 목표 창 열기 500ms·500화 2초)을 "그 목표로 시작"으로 확정. SPEC 8장 측정 규칙, CLAUDE.md 한글 규칙.
- **결과**: ① PLAN 미결정 26을 6장으로 옮김. ② perf.sh(부하 평균 9~12): 되돌리기 창 열기 87ms 통과, 모두 되돌리기 2.86초·전체 바꾸기 2.88초·앱 실행 562ms 미달, 나머지 통과. `testReplaceAll500`만 따로 두 번: 바꾸기 1.80·1.93초, 모두 되돌리기 1.79·1.82초, 창 열기 74·78ms(통과). 바꾸기와 되돌리기는 같은 쓰기 길(`rewriteEach`)이라 "perf.sh 안에서만 느림"(미결정 20 ⓓ)과 같은 모양으로 보고 17단계에서 함께 찾는다. ③ 한글 체크리스트 17~19번 추가. ④ 실제 앱(검증 스킬, 실제 키 코드, 두벌식)으로 세 항목 확인(증거 `build/verify/evidence/20261124-094001-hangul-replace-revert`): `바꿀 말`의 '준'을 조합하던 중 `모두 바꾸기` → 확인 창 `'민준'(으)로`, 디스크도 '민준' 3곳. 확인 창을 엔터로 누르고 곧바로 "가나 "를 10번 쉬지 않고 침 → 10번 모두 온전, 손을 멈춘 뒤 두 회차의 '민준'만 '도윤'으로. "가"를 조합하던 중 `전체 바꾸기 되돌리기…` → "가"가 확정되어 남고 '도윤'만 '민준'으로, 이어 친 "나 가"도 그대로. 코드 변경 없음. NovelCore 175개·앱 227개(건너뜀 14) 통과.
