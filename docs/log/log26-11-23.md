## 검색 버튼 깜빡임

- **이유**: 사용자가 "검색 아이콘 버튼을 누르면 깜빡여서 효과가 겹쳐 있는 것 같다"고 알렸다.
- **근거**: 실제 앱에 임시 로그를 넣어 확인. 검색 패널은 처음 그릴 때 왼쪽 여백 8pt로 그렸다가 77ms 뒤 잰 값 19pt로 다시 그렸다(`search body inset 8.0` → `search inset 19.0`). 패널 내용 전체가 11pt 옆으로 튀었다. 회차 목록도 검색을 닫고 돌아올 때마다 8 → 4로 튀었다. 두 패널 모두 잰 값을 자기 `@State`에 들고 있어서, 사이드바가 `if/else`로 패널을 바꿀 때마다 값이 사라지고 다시 쟀다.
- **결과**: 잰 여백을 작업 공간(`WorkspaceView`)이 패널별로 들고 바인딩으로 넘긴다. 검색 패널은 창에서 처음 열 때만 잴 때까지 숨긴다. 고친 뒤 로그: 처음 열 때 `measured=nil visible=false` → `19 visible=true`, 두 번째부터 바로 `19 visible=true`. NovelCore 159개·앱 217개(건너뜀 14) 통과.
- **에러**: 처음 넣은 `print` 로그는 파이프로 나가 버퍼에 묶여 `app.log`에 안 찍혔다. 디자인 스냅샷 실행은 도중에 멈춰(중단됨) 반쯤 바뀐 스냅샷 그림 2장을 되돌렸다.
- **수정**: 로그를 `NSLog`로 바꿔 확인했고, 확인 뒤 임시 로그는 모두 지웠다.

## 13단계 ④ 되돌리기 (51c21cc NovelCore, 이어서 앱 커밋)

- **이유**: PLAN 14장 7번의 다음 순서. 사용자 답 "메모리만, 진행해"(되돌리기 기록을 앱을 끄면 사라지게).
- **근거**: PLAN 14장 5번(묻지 않고 바꾼 자리만, 고른 회차만, 편집기 ⌘Z는 그 회차만, 다시 바꾸기), 미결정 21. 기존 `TextDiff`는 화면용이라 위치를 따라가지 못해 새로 만들었다.
- **결과**: NovelCore `TextTracking`·`ReplaceRevert`·`TextChange`, 스냅샷 종류 `revert`. 앱은 바꾸기·되돌리기·다시 바꾸기를 `EpisodeAutosaver.rewrite` 한 길로 합쳤다(편집기 `replaceOccurrences`가 자리마다 다른 말을 받음: 자모로 풀어 쓴 원래 말·대소문자가 자리마다 다를 수 있어서). 되돌리기 창·토스트 두 버튼·편집 메뉴·창 실행 취소 등록·편집기 ⌘Z 토스트. 실제 앱으로 토스트·메뉴·사이드바 ⌘Z·창 다시 실행·편집기 ⌘Z 다섯 진입로를 확인하고 디스크로 증명(표시 문구 VREPL·VNEW 개수, `revert` 스냅샷과 메모). NovelCore 175개, 앱 223개 통과. perf: 창 열기 83ms, 모두 되돌리기 500화 1.86초.
- **에러**: ① 줄 비교 전 앞뒤 같은 부분을 문단 중간에서 잘라 빈 줄 조각끼리 짝지어, 새로 쓴 문단의 같은 말을 바꾼 자리로 잘못 따라갔다(테스트 2개 실패). ② 긴 문단 하나에서 양 끝을 모두 고친 경우를 테스트가 요구했는데, 그건 주석이 약속한 것보다 어려운 경우였다. ③ 테스트에서 ⌘Z가 바꾸기·입력·되돌리기를 한꺼번에 되돌림(이벤트가 없어 입력 묶음이 안 닫힘). ④ 실제 앱에서 체크 칸이 손쉬운 사용으로 눌리지 않음(그림 + 탭 동작). ⑤ 메모 날짜가 `11. 23.`(지역 서식). ⑥ 모두 되돌리기 500화 3.04초 미달: 회차를 하나씩 돌려서(회차마다 7.6ms × 397). ⑦ 컴퓨터 유스의 ⌘Z 키가 ⌘A로 들어가 편집기 ⌘Z 확인이 한 번 헛돌았고, 토스트가 5초 뒤 사라진 다음에 눌렀다.
- **수정**: ① 앞뒤 자르기를 두 글 모두의 줄 경계로 맞추고, 짝이 안 맞은 묶음 안에서도 같은 앞뒤를 먼저 남김. ② 테스트를 한 곳 고침으로 바로잡음(양 끝 고침은 되돌리지 않고 "그대로"로 세는 안전한 쪽). ③ 테스트에서 묶음을 직접 닫음. ④ 실제 체크 상자(`Toggle` checkbox)로. ⑤ 날짜를 직접 만듦 + 테스트. ⑥ 바꾸기의 8개 겹치기를 `rewriteEach`로 빼 셋이 함께 씀. ⑦ 검증 스킬의 실제 키 코드 도구(`keys c6`)로 다시 확인, 남은 회차 확인은 편집 메뉴로.

## 버그 점검 (689c7c9 휴지통, 이어서 앱 커밋)

- **이유**: 사용자 요청 "전체적으로 버그 체크 해줘".
- **근거**: 읽기 전용 검토 에이전트가 코드 경로를 따라 9개를 냈고, 하나씩 코드와 로그로 확인했다.
- **결과**: 고침 — 휴지통 보내기 중 바꾸기가 쓰면 파일이 되살아남(`leaving`으로 먼저 막음), 바꾸기 도중 종료·창 닫기(`beginBulkRewrite`로 끝날 때까지 기다림), 표시된 글자 없이 조합하는 중에 열린 회차를 고쳐 글자가 쪼개짐(입력 0.5초 멈춘 뒤 고침, 테스트), 다시 바꾸기 기록 유실(작업 중이면 손대지 않음), "이미 되돌림" 숫자에 읽지 못한 회차가 섞임(따로 안내), 비교 "비교하는 중…" 멈춤. 남김 — 충돌 남은 채 종료(미결정 27), 기다리는 사이 새로 친 말, 창 실행 취소가 최근 바꾸기를 여는 것, 디자인 스냅샷 시각.
- **에러**: `leaving`을 넣으며 `ProjectModel.init` 안의 클로저에서 `guard let self` 뒤 `project`를 썼더니 init 매개변수(연 때의 목록)를 가리켜, 나중에 추가한 회차를 "목록에 없음"으로 보고 바꾸지 않았다(테스트 2개 실패). 로그로 `self?.project`는 true, `project`는 false인 것을 확인.
- **수정**: `self.project`·`self.leaving`으로 쓰고 까닭을 주석으로 남김. 같은 init의 다른 클로저는 이미 `self?.`로 써서 문제없음을 확인.
