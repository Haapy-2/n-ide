## 9단계: 글자 수와 상태 표시줄 (`08a0d02`)
- **이유**: 웹소설은 회차 분량(보통 5,000자 안팎)을 맞춰 연재하므로 쓰는 동안 글자 수와 목표 진행률이 보여야 한다.
- **근거**: SPEC 7장 3번·8장("먼저 재고 느리면 증분"), PLAN 4장 9단계·결정 사항 3·6, DESIGN 4장 상태 줄·사이드바, PERFORMANCE 2장(키 입력 경로).
- **결정**:
  - NovelCore `CharacterCount`: `Character` 단위, 공백 포함 = 줄바꿈만 뺌, 공백 제외 = 모든 빈칸 문자(전각 공백 포함) 뺌. 목표 기준 `CharacterCountBasis`.
  - 글자 수 저장 위치: `project.json`의 회차 정보(`characterCount`, 선택 값). 사이드바가 본문을 읽지 않고 보여주려면 필요. 본문에서 다시 셀 수 있는 값이라, 저장은 3초 미뤄 묶고(입력 멈춤마다 쓰지 않음) 창을 닫을 때 남은 것을 쓴다. 형식 버전은 올리지 않음(없는 키는 nil로 읽고, 옛 앱은 모르는 키를 무시).
  - 세는 때: 키 입력마다 세지 않고 입력이 0.3초 멈추면 본문을 한 번 복사해 메인 스레드 밖에서 전체를 센다(`CharacterCounter`). 텍스트 저장소 알림으로 입력·실행 취소·외부 변경 다시 읽기를 모두 잡는다. 키 입력 때는 시각만 적고, 기다리는 작업은 하나만 둔다.
  - 회차 전환: project.json에 있던 값을 바로 보여주고 새로 센 값으로 바꾼다. 떠나는 회차에 아직 안 센 입력이 있으면 편집기에 옛 본문이 남아 있을 때 먼저 센다.
  - 상태 줄(`StatusBar`): 편집 영역 아래 28pt, 본문 폭에 맞춤. 왼쪽 글자 수(설정의 표시 방식), 오른쪽 진행률 `24%` + 2pt accent 막대(100% 넘으면 숫자만 계속), 오른쪽 끝 저장 상태(저장 중…/저장 실패 · 다시 시도 중/저장 실패 · 원고는 메모리에 있음, 마지막은 누르면 이유). 편집기 위에 겹치지 않게 아래에 따로 둠.
  - 흐려짐(`StatusBarFade`): 타이핑 1초 뒤 150ms로 사라지고 입력 1.5초 멈춤·마우스 움직임에 나타남. SwiftUI 상태는 한 번 타이핑하는 동안 두 번만 바뀐다. 실패 표시는 흐려지지 않음. 동작 줄이기면 애니메이션 없음.
  - "다시 시도 중" 표시를 위해 `SaveQueue.save(..., onRetry:)` 추가, 자동 저장 상태에 `.retrying`.
  - 목표 글자 수: 회차 메뉴·사이드바 우클릭 "목표 글자 수…"(숫자만 받음, 0 이하 무시, ⌘Z로 되돌림). 이름 변경·순서 변경을 되돌려도 글자 수는 지금 값을 이어받음.
  - 설정 키: `characterCountDisplay`(`CharacterCountDisplay`: both/withSpaces/withoutSpaces, 기본 both), `characterCountGoalBasis`(기본 withSpaces). 설정 창은 10단계 몫이라 화면은 아직 없음(10단계 세션과 키 이름 약속함).
  - `make-dummy-novel`이 글자 수도 project.json에 넣는다.
- **측정(전체 계산 속도, 릴리스)**: 5,000자 0.3ms, 10만 자 6ms, 편집기에서 꺼낸 문자열(NSString) 10만 자 20ms → 증분 계산은 만들지 않음.
  - **수정**: 세기 전에 Swift 문자열로 바꾸면(`makeContiguousUTF8`) 편집기 문자열 10만 자 20ms → 10ms. NovelCore 안에서 한다.
- **에러 1**: 테스트 기대값을 손으로 잘못 셈(대사 문단 공백 제외 15→16, "방금 쓴 문장" 6→7). 코드는 맞았음.
- **에러 2**: 상대 경로로 준 더미 작품 경로를 `swift test`가 패키지 폴더 기준으로 읽어 못 찾음 → 절대 경로로.
- **결과**: NovelCore 테스트 57개, 앱 테스트 41개(건너뜀 3) 통과. 성능: 키 입력 p95 1.3ms(글자 수 세기·흐려짐 포함해 잼), 회차 전환 2.3ms, 500회차 열기 1.3ms(project.json에 글자 수가 들어가 0.7→1.3ms), 앱 실행 524.7ms(기존 미달, 17단계), 대기 메모리 86MB.
  - 메모리가 지난번 73MB보다 높아 같은 때 이전 커밋 릴리스 빌드와 번갈아 3번씩 잼: 이전 70·74·76MB, 이번 84·75·75MB → 차이 없음(흔들림).
- **남긴 것**: 앱을 끌 때는 미뤄 둔 글자 수 저장을 기다리지 않는다(종료 직전 3초 안에 바뀐 글자 수만 해당, 그 회차를 열면 다시 셈). 글자 수가 없는 옛 작품·복구로 다시 만든 목록의 회차는 열기 전까지 사이드바 글자 수가 비어 있다.

## 진행률 모양 수정 (`6adef56`)
- **이유**: 사용자 지적. 다크 모드에서 `97%` 아래 막대의 남은 부분이 안 보였다(트랙이 `rule` 색이라 종이와 거의 같음). 이미지처럼 고리 모양을 원하고, 설정에서 막대/원을 고르고 싶다고 함.
- **근거**: 사용자 요청과 첨부 이미지 2장, 시안 두 가지를 스레드에 그려 보여주고 "진행" 승인. 키 이름은 10단계 쪽과 맞춤(`goalProgressStyle`, `GoalProgressStyle.bar/.ring`), 기본값은 원(사용자 승인).
- **결과**: 원 = 지름 14pt·선 2pt 고리, 막대 = 숫자 옆 80×4pt 캡슐. 트랙은 inkMuted 35%. 100%를 넘으면 모양은 가득, 숫자만 오름. 마우스를 올리면 남은 글자 수. 설정 창의 고르는 칸은 10단계 몫. Xcode 미리보기 "목표 진행률" 추가.
- **에러**: 고리 끝을 둥글게(`.round`) 하니 97%에서 남은 3% 틈을 둥근 끝이 덮어 안 보였다(라이트·다크로 그려서 확인).
  - **수정**: 끝을 각지게(`.butt`).
