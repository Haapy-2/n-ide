## 7단계: 회차 관리 (`85c1f73`)
- **결정**: `ProjectModel`이 회차 목록을 바꾸고 `project.json`을 같은 저장 줄로 저장. 새 회차는 빈 파일 먼저 쓰고 목록에 넣음(목록에만 있고 파일 없는 회차 방지). 휴지통으로 못 옮기면 아무것도 바꾸지 않음(영구 삭제로 대신하지 않음). 지우기 전에 마지막 내용 저장, 지운 뒤 자동 저장이 파일을 되살리지 않게 저장 정보 정리. 회차 메뉴 단축키: 새 회차 ⌘N, 이전/다음 ⌥⌘↑↓, 이름 변경 ⇧⌘R, 휴지통 ⌥⌘⌫. 테스트는 진짜 휴지통 대신 테스트 폴더로 옮기도록 바꿔 끼움.
- **에러 1**: 이웃 회차 이동 명령의 클로저 타입 추론 실패로 빌드 오류 → 별도 함수로 분리.
- **사이드바 ↩·⌘⌫** (`cfa1af6`, 사용자 재시도 요청): 사이드바가 키보드 초점을 받게 하고, 회차 클릭 때 편집기가 초점을 빼앗지 않게. 앱을 처음 열 때는 편집기에 초점(실행 측정으로 확인).
- **에러 2**: ⌘⌫가 안 먹힘(사용자 보고). ⌘ 조합은 macOS가 메뉴에 먼저 보냄.
  - **수정** (`b10d3f8`): 사이드바에 초점이 있을 때만 메뉴 단축키를 ⌘⌫로 바꿈(편집기에서는 ⌥⌘⌫, 편집기 ⌘⌫는 "줄 앞까지 지우기" 유지).
- **순서 변경 되돌리기** (`f480d85`): 사용자 요청. 초점 위치로 되돌리기 기록 분리(사이드바 = 회차 목록, 본문 = 글자).
- **에러 3**: 되돌리기 테스트에서 앱이 죽음. 되돌리기 처리 안에서 다시 실행 기록을 비동기(Task)로 등록해 UndoManager 묶음 밖에서 등록됨.
  - **수정**: 기록은 그 자리에서 동기로, 파일 저장만 Task로.
- **새 회차·휴지통 되돌리기** (`fef925d`): 사용자 요청. 휴지통에서 원래 자리·본문 그대로 꺼냄.
- **회차 사이 틈 클릭 무반응** (`fef925d`): 칸 사이 1pt 틈과 시스템 최소 줄 높이 → 틈까지 클릭 영역에 포함, 최소 줄 높이 0.
- **되돌리기 정책 문서화** (`3e6f8ae`): PLAN 9장(메뉴에 보이기, 전체 바꾸기, 회차 묶음).
- **성능(7단계 측정)**: 키 입력 p95 1.1ms, 회차 전환 2.1ms, 앱 실행 중앙값 460ms(통과, 단 1.1초·약 6분짜리 튀는 값이 한 번씩 — 기기 상태로 추정, 미확인), 대기 메모리 113MB(미달, 17단계).

## 8단계: 외부 변경 처리 (`83f11eb`)
- **이유**: 다른 편집기(텍스트 편집기, git 등)로 회차 파일을 고쳤을 때 앱이 모르고 덮어쓰면 원고가 사라진다.
- **근거**: SPEC 7장 "외부 변경", PLAN 4장 8단계, PLAN 5장 "수정 시각+크기로 1차 확인, 다르면 내용 비교".
- **결정**:
  - NovelCore `ExternalChange.swift`: `FileStamp`(수정 시각·크기), `DiskVersion`(마지막으로 읽거나 쓴 상태), `checkEpisode`(시각·크기가 같으면 안 읽음, 다르면 내용 비교, 내용이 같으면 변경 아님), `writeEpisode(_:id:ifUnchangedSince:)`(저장 직전 확인, 바뀌었으면 쓰지 않고 `.conflict`). 파일이 지워졌으면 앱 내용으로 다시 쓴다.
  - NovelCore `ConflictSnapshot.swift`: `snapshots/<회차ID>/<시각>-conflict.md`. 같은 초면 `-2`를 붙이고 덮어쓰지 않는다. 11단계 전까지의 최소 함수.
  - `SaveQueue`에 쓰기 결과를 돌려주는 `save(_:change:writeReturning:)` 추가(충돌을 오류로 던지면 재시도 3번을 해 버려서).
  - 앱: 기준 상태는 `DiskVersions`(잠금은 사전 읽기·쓰기 순간에만, 파일 I/O 동안은 안 잡음 → 메인 스레드가 저장을 기다리지 않음). 창이 키 창이 될 때(`didBecomeKey`) 확인. 앱 쪽 변경(저장 전 입력, 쓰는 중, 조합 중)이 없으면 커서·스크롤 그대로 두고 다시 읽기. 있으면 앱 본문을 메모리에 붙잡고 스냅샷을 남긴 뒤 묻기. 고를 때까지 그 회차는 저장 안 함.
  - **SPEC보다 하나 더**: "이 앱의 내용 쓰기"를 고르면 덮어쓸 바깥 내용도 `-external.md` 스냅샷으로 남긴다. SPEC은 앱 쪽만 남기라고 했지만, 그러면 앱 쪽을 고를 때 바깥 내용이 사라진다(우선순위: 원고 유실 방지).
  - 확인하는 사이 앱 자신의 저장이 끼면 그 결과를 버린다(기준이 바뀌었는지 다시 봄). 진짜 외부 변경이면 그 저장의 직전 확인이 먼저 잡는다.
- **결과**: NovelCore 테스트 10개(총 48), 앱 테스트 8개(총 29) 추가, 모두 통과.
- **성능**: 키 입력 p95 1.1ms, 회차 전환 2.6ms 통과. 앱 실행 중앙값 549ms로 **미달**.
  - 7단계 코드(stash)와 8단계 코드를 같은 때 11번씩 띄워 비교: 521ms 대 511ms → 8단계 탓 아님, 기기 상태 차이로 판단.
- **에러**: perf.sh가 10분 넘게 안 끝남. 실행 측정 중 앱 하나가 "입력 가능" 신호 없이 멈춰 있었음(이벤트 대기 상태). 7단계 코드에서도 11번 중 1번 재현 → 원래 있던 문제. 7단계의 약 6분 값도 이것으로 추정.
  - **효과 없던 시도**: 처음 열 때 사이드바가 초점을 먼저 가져가 편집기가 첫 응답자가 못 된다고 보고 "처음엔 무조건 편집기에 초점"으로 고침 → 12번 중 1번 또 멈춤. 되돌림. 원인 미확인, PROGRESS "알려진 문제"에 적음.
  - perf.sh를 사용자 요청으로 처음부터 다시 돌림(멈춘 실행은 손으로 끝냄).
