# 2026-11-25 작업 기록

## ⌘D 다른 자리 커서를 맨 앞 커서와 같이 깜빡이게

- **이유**: 사용자가 "⌘D로 그린 커서를 원본 커서랑 똑같이 깜박여 줘, 주기는 무조건 똑같이"라고 요청했다. 다른 자리 커서가 깜빡이지 않고 켜진 채로 남았다.
- **근거**: 빈 시험 창(`NSTextView` 하위 클래스, 레이어 있음·없음 둘 다)에서 호출을 찍어 봄: 시스템은 약 0.56초마다 커서 칸을 다시 그리고, 켤 때만 그 그리기 바로 뒤에 `drawInsertionPoint(turnedOn: true)`를 부른다. 깜빡임으로 끌 때는 `turnedOn: false`를 한 번도 부르지 않았다. 기존 코드는 `turnedOn` 값으로 켜고 껐기 때문에 한 번 켜지면 창이 비활성화될 때까지 꺼지지 않았다. 또 커서 칸 다시 그리기 요청에 다른 칸을 붙이면 한 그리기에 함께 들어오고 `drawInsertionPoint`의 그리기 범위도 그만큼 넓어짐을 확인했다.
- **결과**: 따로 타이머 없이 시스템 깜빡임에 묶음. ① 가는 커서 칸 다시 그리기 요청(`isCaretSized`)에 다른 자리 커서 칸을 붙인다. ② 그리기가 맨 앞 커서 칸을 덮으면(`needsToDraw`) 다른 커서도 꺼짐. ③ `drawInsertionPoint(turnedOn: true)` 안에서 맨 앞 커서와 함께 다른 커서도 그린다(같은 그리기, 같은 화면 갱신). 앱 테스트 2개(켜는 그리기에 다른 커서가 그려짐, 다시 그리면 사라짐: 고치기 전 둘 다 실패를 확인). 실제 앱(앞에 띄운 창, ⌘D 세 자리 + 스페이스)에서 16번 찍어 매번 세 커서가 모두 켜지거나 모두 꺼짐, 하나만 다른 순간 없음(증거 `build/verify/evidence/20261125-103339-multi-cursor-blink`, 화면은 대화에 남김). NovelCore 201개·앱 252개(건너뜀 15) 통과. 성능은 따로 재지 않음: 바뀐 것은 여러 커서일 때 깜빡임마다 다른 커서 칸 계산뿐이고, 커서 100개 키 입력 측정은 13-2 ④에서 한다.
- **에러**: ① 첫 시험 창은 터미널에서 띄워 키 창이 되지 않아 커서가 깜빡이지 않음. ② zsh에서 `$mode`가 낱말로 나뉘지 않아 일부 측정 모드가 꺼진 채로 돌았다. ③ 꺼짐 테스트의 비교 그림을 새 편집기로 만들었더니 배경이 비어 있었다. ④ 백그라운드 조작으로는 창이 키 창이 아니라 실제 앱에서 깜빡임이 안 보인다.
- **수정**: ① 조금 뒤에 `activate`. ② 측정은 레이어 있음/없음 결과만 씀. ③ 같은 편집기에서 여러 커서만 버리고 다시 그려 비교. ④ 사용자 허락을 받고 검증 앱을 맨 앞에 띄워 확인. 기능 지도에 적음.
