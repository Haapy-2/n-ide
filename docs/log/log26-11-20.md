## 검증 스킬 verify-noveleditor 추가 (8e0aa47)

- **이유**: 테스트 통과만으로는 실제 앱에서도 동작하는지 알 수 없다. 에이전트가 앱을 띄워 사용자처럼 조작하고 디스크 파일로 증명할 수 있는 정해진 방법이 필요했다.
- **근거**: 사용자 요청(pstack `create-verification-skill`). `.claude/` 새 루트 항목과 사용자 설정 백업·복원 방식은 사용자 허락을 받았다.
- **결과**: `.claude/skills/verify-noveleditor/` 아래 `SKILL.md`, `verify.sh`(launch·doctor·evidence·cleanup), `features/` 기능 지도 4개. 조작은 computer-use 백그라운드 도구(`app_*`)로 한다. 실행 시 `NOVEL_PERF_OPEN`으로 작은 검증 작품(3회차)을 바로 연다. 시작할 때 UserDefaults를 `build/verify/`에 백업하고, 정리할 때 되돌린다. 처음부터 끝까지 한 번 돌려 봤다: 본문 끝에 `VERIFY01` 입력 → `파일 > 지금 저장` → `dummy-0001.md`에 문구가 있음 → 증거 복사 → 정리 뒤 증거가 남아 있고 앱이 꺼졌으며 설정이 되돌아갔다.
- **에러**: `screencapture`가 "could not create image from display"로 실패했다(터미널에 화면 기록 권한 없음).
- **수정**: 화면 증거는 `app_screenshot` 결과로 대신하고 디스크 파일을 주 증거로 삼았다. 한글 조합(IME)은 `app_type`으로 재현되지 않아 사람 확인 체크리스트로 남긴다고 스킬에 적었다.

## 전체 점검: 저장 실패 원고 지키기 (8ff73f1)

- **이유**: 사용자 요청("코드를 전체 스캔해 버그 가능성 있는 곳을 고쳐"). 원고 유실이 가장 심각한 버그라 저장 경로부터 봤다.
- **근거**: 읽기 전용 점검 두 갈래(저장 경로, 편집기·UI). 결과는 코드에서 직접 다시 확인했고, 고치기 전에 실패하는 테스트로 재현했다.
- **결과**:
  - `flush`가 열린 회차만 다시 저장해서, 저장에 실패한 다른 회차 원고는 창을 닫으면 조용히 사라졌다 → 메모리에 남은 다른 회차도 다시 저장한다.
  - 저장 실패한 회차를 휴지통으로 보내면 마지막 원고를 버렸다 → 못 쓴 원고가 있으면 옮기지 않는다(`UnsavedEpisodeError`).
  - 그래도 못 쓴 채 창을 닫거나 앱을 끄면 경고하고 다른 폴더에 `.md`로 내보낼 수 있게 했다(`RescueExport`, 사용자 선택: "경고 + 다른 곳에 저장"). 안 내보내면 저장기를 붙잡아 두고 끌 때 다시 묻는다.
  - A 회차 실패 뒤 B 회차가 저장되면 상태가 "저장 중"에 멈춰 실패 표시가 사라졌다 → 저장이 끝날 때마다 실제 상태로 맞춘다(`settleStatus`).
  - 외부 변경 충돌로 쓰지 않은 저장도 `SaveQueue`가 "썼다"고 기록했다 → `didWrite`로 실제로 쓴 것만 센다.
- **에러**: 새 테스트 두 개가 고치기 전에도 통과했다. 떠날 때 시작한 저장의 재시도가 막힘을 푼 뒤 성공해 버려 상황이 재현되지 않았다.
- **수정**: 떠날 때의 저장이 끝나기를 기다린 뒤 막힘을 풀도록 테스트를 고쳐, 고치기 전 코드에서 실패하는 것을 확인했다. 한 회차만 저장을 실패시키려고 파일 자리에 비어 있지 않은 폴더를 둔다(폴더 권한을 막으면 모든 회차가 실패한다).

## 전체 점검: 편집기·UI (2eb1460)

- **이유**: 같은 점검의 편집기·UI 쪽과, 확신이 낮았던 항목을 확인한 뒤 고쳤다.
- **근거**: 실제 앱(검증 스킬)에서 스냅샷 판 ⌘Z 버그를 재현했다. 휴지통 되돌리기 순서와 project.json 저장 실패는 고치기 전 코드에서 테스트가 실패하는 것을 확인했다.
- **결과**:
  - 스냅샷 판이 떠 있을 때 `편집 > 실행 취소`가 확인 창 없이 방금 만든 회차를 지웠다 → 판이 초점을 받고 되돌리기를 받아 아무것도 하지 않는다. 실제 앱에서 회차가 그대로인 것을 확인했다.
  - 단축키 기록 중 원고 창에서 친 키를 앱 전체에서 삼켰다 → 설정 창이 아닌 창의 키는 넘기고 기록을 취소한다. **실제 앱 확인 못 함**(백그라운드 도구로 두 창에 키를 나눠 보낼 수 없음).
  - 회차 전환·외부 변경 다시 읽기에서 `unmarkText`만 해 입력기가 조합을 끝내지 않았다 → `finishComposition()`(입력기에도 알림). 단위 테스트로 볼 수 없어 `docs/checklist-hangul.md` 손 확인 대상.
  - 회차 본문을 읽지 못하면 앞 회차 글자 수가 남았다 → `CharacterCounter.clear()`.
  - 설정의 회차 목표 칸에 치는 사이 다른 작품 창이 앞으로 오면 그 작품에 값이 들어갔다 → 입력을 버리고 새 작품 값으로 바꾼다.
  - ⌘Z·⇧⌘Z를 바로 이어 누르면 목록에는 있는데 파일은 휴지통에 있는 회차가 생겼다 → 파일 되돌리기를 순서대로 하나씩 한다.
  - `project.json.bak` 쓰기 실패가 본 저장까지 막았고, project.json 저장 실패를 끌 때 묻지 않았다 → 백업은 덤으로, 실패한 저장은 끌 때 다시 시도하고 그래도 안 되면 묻는다.
- **에러**: 스냅샷 판 첫 시도(`onCommand`만 붙이기)는 효과가 없었다. 판을 열면 편집기가 초점을 놓아 창이 첫 응답자가 되고, 그러면 SwiftUI의 `onCommand`까지 명령이 오지 않는다.
- **수정**: 판이 열릴 때 초점을 받게 해(`focusable` + `@FocusState`) 명령이 판에 먼저 오게 했다.
- **안 한 것**: `project.json`에 없는 회차 파일을 열 때 찾아 넣는 일. "작품을 열 때 project.json만 읽는다" 규칙과 부딪혀 사용자 결정이 필요하다. `ClickDebug.swift`(진행 중인 커서 작업의 디버그 로그)는 사용자 작업이라 손대지 않았다. 커밋 전에 지우거나 `#if DEBUG`로 감싸야 한다.
